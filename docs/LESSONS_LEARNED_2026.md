# weixin-reader 项目开发经验与易错点总结（2026-09 完整版）

> 本文档沉淀 2026-09-10 ~ 2026-09-13 三十余轮“多 Agent 独立重查 → 真机取证 → 修复 → 提交上游”全流程中
> 反复踩过的坑与验证有效的方法。此前经验散见于各 commit message 与 docs/WEBKIT_COMPATIBILITY.md 等，
> 本文统一整合为后续开发的复查清单。
> 版本锚点：整理于上游合并 PR #19~#23、发布 v1.8.5 之后。

---

## 一、方法论层（最高价值）

### 1.1 修复顺序铁律：可观测性先行
- **案例**：第五轮修 menu toggle 时（#21），测试探针无输出，盲改了两轮。第三轮给成功路径补 `log::info!`（一行代码）后，一次测试即分清“按键没到 vs 达成”——立刻锁定真根因是 `set_menu(same)` 被 tauri/muda 去重为 no-op。
- **规则**：任何“时灵时不灵”类 bug，先加日志/探针，再动手。**修完不要删日志**——它就是用户复现问题时唯一的现场证词。

### 1.2 真机取证 > 一切推测
- 本项目每一条上游 PR 的 Root Cause 都是 CDP（WebView2 远程调试 9333 端口）现场实测取得，无一例外：
  - #20 注入即崩：CDP 读到 `window.atreaderRuntime` ABSENT、`wxrd-* 元素 0 个`
  - #21 全屏广播丢失：真机探针 `inFullscreen 恒 false`
  - #23 滑杆：CDP dispatch input 事件
- **CDP 分界测定法**（可复用技巧）：页面内 dispatch 合成 KeyboardEvent 立即有后端响应 → 断定问题在 OS 输入层而非页面逻辑。这是分离两层的手术刀。
- **取证前清场**：模拟测试写入 cookie 会残留污染后续读数（双 wr_theme 并存）。实测前先 `max-age=0` 清场。

### 1.3 UI 决策先回历史基线
- **案例**：dev.14 把两侧留白拉成与正文同色“沉浸”，用户反馈观感劣化。回查 v1.7.4 源码，原注释早有设计红线：*“不覆盖 body 背景：正文卡片与页面底色保留色差，圆角才可见”*。
- **规则**：视觉/交互决策类改动，先查历史版本的原始设计意图；**原注释里的设计警告就是新改动的红线**。

### 1.4 每次开工先看分叉
- **事故**：dev.3 安装包带着已修 bug 的回归——本地 dev 缺失 origin/dev 整条修复链，修复在但从未进包。
- **规则**：每次开工 `git fetch && git log HEAD..origin/dev`，dev.1~dev.7 三个包全部因此报废。
- 同源教训：主线重置会孤儿化已合并能力（v1.8.4 的 capabilities 里 `allow-set-theme` 成无主尸体即证据）——重置后要对照归档 tag 做 capability-by-capability 回收审计。

### 1.5 “探针即验收”是错的
- 用户批评原话：“你就觉得好了？你能不能好好弄？”——修完只跑探针不看真实双向行为。
- 规则：验收必须覆盖**用户真实操作序列**。探针读数只是链路证据，UI 最终验收得走“开→关→开”完整循环。

## 二、平台层（Tauri 2.11 / WebView2 / Windows）

### 2.1 Windows 测试基础设施（PR #19）
- tauri_build 只把 common-controls v6 manifest 用 `rustc-link-arg-bins` 链给 bin target；**cargo test 的测试宿主属 lib target 拿不到** → comctl32 绑 WinSxS 5.82 旧版 → 缺 `TaskDialogIndirect` → STATUS_ENTRYPOINT_NOT_FOUND。
- 但也**不能对所有产物重复链接 resource.lib**：bin 目标同时收到两份 RT_MANIFEST(1) → CVT1100/LNK1123。
- Windows dev profile 的 bin 全目标 cargo test 至今存在 LNK1241（tauri_build resource.lib 与我们的 test-manifest.lib 各带 ID=1 RT_MANIFEST）——用 `cargo test --lib`（见 test/README.md）。
- CI 只在 macOS 跑 cargo test → Windows 特有缺陷全是 CI 盲区，必须本地验证。

### 2.2 文档早期注入时序（PR #20，六级修复链）
- WebView2 在**文档解析最早期**执行注入脚本，`documentElement=null`，`MutationObserver.observe(null)` 抛 TypeError。
- 调用点若在 main() try 块外——单异常炸穿整链（快捷键/样式面板/AppRuntime 全灭）。且 atreader_injected 防重入 flag 已置位，不会重注。
- 规则：注入脚本中任何“增强能力挂载”（转发器、悬浮件）都用独立 try/catch 容错降级，失败只损失该特性绝不连累核心链 AppRuntime 初始化。
- 同源：嵌套 iframe 需**每个已挂文档递归配 MutationObserver**（单层观察器永不发现 depth>1 的正文 frame）。

### 2.3 菜单栏 Win32 层（PR #21，四层根因）
- `set_menu(same Object)` 被 tauri/muda 幂等去重为 no-op——摘除态（GetMenu=0）永不恢复。要用 `rebuild_full_menu` 全新实例。
- 事件广搪（fullscreen-changed）与注入 listen 注册有竞速：非持久广播在订阅前发生即丢失。真相源必须改“随问随答”命令（is_main_fullscreen），事件降级为加速器。
- 层叠压制：微信 readerTopBar(z=80,fixed) 压住按钮矩形边角——DOM 天然命中不可达。自定义命中区一律在 document 捕获阶段做几何判定。**elementFromPoint 是层叠真相而非需求真相**。
- 最终自愈兜底：same-position `SetWindowPos + SWP_FRAMECHANGED` 强制非客户区重算。

### 2.4 微信读书主题信号（PR #22）
- 新版页面**没有** body.wr_whiteTheme DOM 类（上游 v1.8.4 也踩此坑：恒判 dark）。真信号是 cookie `wr_theme=dark|light`。
- 多值 cookie 并存时检测取**最后一个**匹配；js 可写入但写入会制造双值——读方要防御。
- 两处消费方判据优先级互为镜像 → set_theme 双写竞速。任何共享信号必须**单一共享实现模块**（core/weread_theme.ts）。

### 2.5 行尾/编码
- 本仓库 mixed EOL 是常态（工作区 CRLF、索引 LF），Python 补丁脚本必须按目标文件**逐文件探测 EOL** 再拼锚串；拼完 `git diff --check`。
- Git Bash heredoc 里写 CRLF 字面串会被转义破坏——用临时 .py 文件方式落盘。

## 三、工程链路层

### 3.1 IPC 命令注册链不可拆（5 条 PR 分批最大教训）
- 新命令 = build.rs AppManifest + lib.rs generate_handler + capabilities 权限 + permissions/autogenerated toml + check-ipc 期望清单，**五点必须同 PR**——check:ipc 任一缺失当场红。
- check-ipc.ts 里有硬编码 expectedMainCommands 数组，加命令要记得同步（此前 miss 过 is_main/reveal）。

### 3.2 构建产物治理
- inject.js / local_reader.js 是编译产物，手工拼合必碎。规则：**冲突时取 HEAD 终态 → 重跑两个构建器 → 重新提交**。CI 有 `git diff --exit-code -- src/scripts/inject.js` 双保险。
- 每次“改源码”提交后必须重建产物并同 commit（dev.8 的 local_reader.js 差 3 分钟时序事故教训）。
- 产物里验证锚点：`git show HEAD:src/scripts/inject.js | grep -c '<新选择器>'` 须 ≥1。

### 3.3 打包与发布
- release/ 归档**只增不删**（用户依赖回退）。clear_release.ts 已加安装包名硬拒绝。
- 本地 dev 打包约定：`bundle.targets=["nsis"]` 只对本地构建生效，**打包后必须还原 tauri.conf.json**。
- 签名：本地 .tauri/dev-updater.key 密码 none（.gitignore 排除）；dev 包不产 .sig；CI 正式更新通道走 GitHub secrets。dev key 与 CI pubkey 不匹配属预期。

### 3.4 测试隔离
- bun 全量串跑存在 1/3 频率跨文件污染（真实计时器 + cookie 残留）。修复模式：beforeEach/afterEach 清场；watcher 契约用例补 mount 前置（路径+容器）——此前 0 调用根因是 mountPanel 有阅读页路径门。
- happy-dom 的 MutationObserver 对 classList.remove 有不派发行为——测试换显式路由事件驱动。

### 3.5 多 Agent 分批提交 PR 流程（本项目最终形态）
1. 终审表按**文件清单**分组（不按时间/PR 主题想象），先 `git merge-tree` 预判冲突；
2. 单文件跨多条 CL 时让后位 CL 整文件携带（产物类不可 hunk 拆分）；
3. 版本三件套（package/Cargo/tauri.conf）必须原子——check:version 三处强一致是硬约束；
4. 每分支交付前跑四门禁（bun/typecheck/check-ipc/check:version）；产物在末位 PR=终态字节（`pr5==dev --stat` 零差异验收）；
5. 文书格式：问题（用户可见症状）→ 根因（一句话因果链）→ 修复 → 验证（具体命令+退出码/CDP 读数），不写 AI 废话。
